# Datasets

## Which dataset to use

| Role | Path | Status |
|---|---|---|
| **Research evaluation dataset** (authoritative) | `datasets/csa_ppe_v1_clean/` | Leakage-free. Use for all training and evaluation. |
| Original audit / reference copy | `datasets/csa_ppe_v1/` | Unmodified. Contains 38 exact duplicate images across and within splits. **Do not use for evaluation.** |

The clean dataset is built from the original by `scripts/build_clean_dataset.py`, which is
deterministic. Rebuilding gives the same files. The clean dataset itself is git-ignored (images
are not redistributed; see `datasets/LICENSES.md`). The record of every removal is committed:
`datasets/splits/csa_ppe_v1_clean_removed.csv`.

Both `data.yaml` files contain an absolute `path` from the development Mac. You do not need to edit
them: `training/train_detector.py` writes `data_resolved.yaml` next to each run, with `path` set to the
folder that actually holds the data.

## Files that must never be committed

- `csa_ppe_v1.zip` (517 MiB, the original archive). Kept locally for Colab/Drive upload.
- `datasets/csa_ppe_v1/`, `datasets/csa_ppe_v1_clean/`, `datasets/raw/` (all images).
- Only `datasets/splits/` (manifests and the removal CSV) is tracked.

## Why the clean dataset exists

The pre-training audit (`results/dataset_audit.json`, SHA-256 not used there; that audit used MD5)
found exact duplicate images:
- 8 **test** images are byte-identical to training images.
- 3 **validation** images are byte-identical to training images.
- 1 test image is byte-identical to a validation image.
- 24 groups repeat within train and 2 within valid.

Evaluating on the original test split would therefore measure memorisation of duplicates as
well as generalisation. Results on it would be inflated, so it is not used as-is.

## Cleanup policy (deterministic)

1. Hash every image with SHA-256.
2. For each hash with more than one file, keep **one** copy. Preference: test, then valid, then
   train. Ties: smallest file name. The test split is never reduced because of a duplicate;
   copies are removed from train and valid instead.
3. Copy kept images and their label files byte-for-byte. Nothing is re-encoded or edited.
4. Record every removed file, its hash, and the kept copy.
5. Verify from the rebuilt files: zero exact-image overlap across splits, zero duplicates within
   a split, every image has a label, every label has an image, class names unchanged.

Images are removed, never edited. Labels are removed only together with their image.

## What is not yet checked

- **Near-duplicates** (re-encoded, resized or cropped copies of the same photo) are not detected
  by exact hashing. Their number is NOT YET MEASURED. Perceptual hashing or manual review is needed.
- **Label agreement between duplicate copies** was not checked. The policy keeps one copy and
  drops the others, so any conflicting labels on the dropped copies are discarded without review.
- **Source balance.** The dataset merges CHV and SHWD. Source-level composition after cleanup is
  not reported here.

## Original dataset facts (audit)

- Labels: no malformed lines, no invalid class IDs, no out-of-range boxes (`results/dataset_audit.json`).
- One empty label file in the original valid split. It is kept as a negative image.

## Known discrepancy (open)

The stored audit `results/audits/csa_ppe_v1/audit.json` and the week-3 note in
`docs/dataset_audit.md` report **11,433 instances and 5,269 helmet boxes**.
A recount on 2026-10-26 of the current original files, with both a direct label count and the
project's own YOLO parser (`csa_yolo/data/yolo.py`), gives **11,432 instances and 5,268 helmet boxes**.
All other classes agree. Label files were last modified before the audit file (no label file is newer),
so the cause is not an edit after the audit. It is not yet explained. The current files are used
as the reference. No conclusion depends on the single box. Investigation step: regenerate the
audit from scratch with the current parser and compare per image.
